# 通信履歴の保持期間（2026-10-25）

## 範囲

観測版の日常利用とプライバシー管理のため、既存のセッション履歴に保持期間を追加した。実測履歴・デモ履歴は別のRustメモリに置き、Preferences.historyRetentionだけを既存文書へ原子的に保存する。バックアップは従来のルールのみで、履歴や保持設定を新たに含めない。デモ画面の設定も共有の保持設定を変更する。実測履歴を画面に出さないことと、内部に保持しないことを区別する。

| 設定値 | 動作 |
| --- | --- |
| session | 既定。現在のセッション中、最大500件。従来どおり |
| off | 履歴を残さず、既存の履歴も削除 |
| 15m / 1h / 24h | 初回観測時刻から指定期間内の行のみ、最大500件 |

履歴は新しく観測された接続を記録するものであり、全接続試行や通信内容のログではない。現在の接続が継続していても初回観測時刻を更新しない。経過期間の境界（年齢が指定秒数以上）と、期間指定時の未来時刻は除外する。現在の観測・署名・ルール・適用確認・ask・他の調査結果は変更しない。

短縮・無効化で消えた行は、延長しても戻さない。記録を再度有効にすると、新たに観測された接続から追加する。継続中の同一接続を自動的に履歴へ再登録しない。デモの現在接続と履歴も分け、デモ切替による履歴の復活を防ぐ。デモの再起動時には新しいサンプルセッションを作る。

## 保存・同期・失敗

SetHistoryRetentionの値はRustの閉じたenumで検証する。旧文書のフィールド欠落はsessionとし、不正な値を無制限保持へ読み替えない。共有Mutex内で既存の文書保存を完了してから履歴を破棄する。保存失敗は設定を巻き戻し、履歴を削除しない。更新インストール中は他の文書変更と同じく拒否する。

成功した設定変更／次の観測更新時に、実測・デモ双方のメモリ履歴をpruneする。観測失敗時も期限処理は続ける。Snapshotにも期限フィルターをかけ、失効行を他のウインドウへ再表示しない。過去に送信済みのSnapshotや画像キャッシュ、他機能の結果を消去する機能ではなく、メモリの安全な消去やOSスワップの不存在までは保証しない。セッション終了時に履歴を永続化しない。ウインドウを閉じてもトレイ常駐は続くため、アプリの終了と区別した説明を3言語ツールチップに置く。

履歴画面と設定で同じ保持UIを使い、全履歴件数・500件上限・終了時消去を表示する。検索後の件数ではなくSnapshot全体の履歴件数。待機中は二重操作を防ぎ、エラーはその場に表示する。現在の通信は削除しないため、履歴なしと現在接続ありは両立する。

ブラウザーは隔離されたデモで、Rustとは別の表示検証用ロジックを使う。デモ履歴をlocalStorageへ保存せず、保存するのは既存文書の設定とデモルールだけ。storageイベントで設定と削除を同期する。実際の期限処理・文書所有・実測はRustが担当する。
