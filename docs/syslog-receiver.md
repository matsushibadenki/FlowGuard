# Syslog受信

更新: 2026-10-17。UDPと改行区切りTCPの手動受信を実装。セキュリティ診断や送信元認証とは別機能。

## 操作と状態

「セキュリティ診断」内のSyslog受信で、このMacの待受IPv4、管理対象の送信元IPv4、ポート、方式、受信時間を指定する。IP制限は認証ではない旨を確認してから開始する。既定ポートは5514、時間は5分。設定は保存せず、起動・再起動・ウインドウ表示で自動再開しない。ルーター側の設定変更、送信元への能動接続、OSファイアウォール設定変更は行わない。

待受は現在UPのローカルIPv4アドレスのみ。プライベート／リンクローカル／ループバックに限定し、公開IP・ワイルドカード・特権ポートを拒否する。送信元も同種のIPv4リテラルを指定し、ループバックとLANを混在させない。ポートは1024〜65535、時間は30〜900秒。IPv6は未対応。ブラウザプレビューは待ち受け・停止・消去を実行しない。

Rust共有状態が開始・停止・記録・選択行・操作世代を所有する。開始中／待受中／停止中の重複開始を拒否し、停止はソケット終了待ちとして表示する。リスナーと全TCP接続を閉じた後で終端状態を公開する。停止後の遅い通知は公開済み記録を増やさず、消去・再開始後の旧操作は拒否する。停止済みの記録は明示消去でき、メモリ以外へ保存しない。本文が機密情報を含む可能性は送信者に依存する。

OSのbind成功後にのみ受信待ちと表示する。ポート使用中や権限エラーを成功と表示しない。ローカルのアドレス・インターフェース・マスクを約2秒ごとに再確認し、変化・取得失敗時に終了する。これはIPへのbindと定期的な変化検出であり、全パケットの到着インターフェースを認証する機構ではない。受信中は更新インストールを拒否し、緊急復旧経路は妨げない。

## 受信方式と信頼境界

UDPは1データグラムを1レコードとして扱う。TCPはLFまたはCRLF区切りのみ。分割到着・複数行を扱い、切断／無通信終了時の未完行を保存しない。octet-countingやTLSは未対応。対応外のフレーミングを自動推測しない。

OSソケットが示す送信元IPを指定値と比較する。本文のホスト名・IP・「認証済み」等の自己申告は判定に使用しない。UDPのIPは偽装可能で、TCPも暗号化・相手認証なし。全記録のtrustは`unverified_source_and_content`とする。接続成功やIP一致から、送信機器の本人性・権限・安全性を推測しない。

先頭のPRI（0〜191）とUTF-8を検査し、本文を外部入力として保持する。これはPRI付きテキストの受信であり、RFC 5424全体やstructured data・署名を検証するパーサーではない。PRI／severityは申告値、時刻はこのMacの受信時刻。送信側時刻、ホスト名、アプリ／PID、攻撃検知は本文から正規化しない。非UTF-8や不正なPRIを拒否する。

制御文字（改行・タブ以外）とbidi方向制御文字を除去し、その事実を表示する。本文はReactのテキストノード／preとして描画し、HTML・Markdown・URL・コードとして実行しない。受信本文をAIへ送らず、ルール・権限・RouterAdapterの認証根拠やSecurityEventへ変換しない。

## 上限と欠落

- 1件4096バイト。TCPの終端CRLFは長さから除く。UDPは4097バイトの固定バッファで超過を判定する。
- 保存対象は毎秒最大20件かつ64KiB。指定元の不正形式もこの流量枠を消費する。
- 保持256件。古いレコードを順に破棄し、破棄数を表示する。画面は50行ずつ追加表示する。
- 1操作で総読取8MiB、20000フレーム、最大15分。到達時に受信を終了する。
- TCP同時2クライアント、無通信2秒、合計1000接続。超過接続は拒否し、合計上限では操作を終了する。
- 非ブロッキングI/Oで1巡の処理数も制限する。変更のある通知は最大約1秒ごと。全記録を含む共有状態自体も保持上限で制限する。

カウンターは既知のアプリ側の観測だけを示す。UDPの切り詰めがあるため読取バイトは下限であり、OSバッファ以前の欠落を測定しない。対象外送信元や流量制限はデータグラム／フレーム／接続の拒否を含み、未完と超過が同じ入力に重なる場合もある。各カウンターの和は一意な損失件数ではない。UDP順序・重複・再送を検証せず、同じ本文を同じ事件と判断しない。保存0件や拒否0件は、到着・欠落なし・安全の証明ではない。

## 検証と保留

単体テストは設定・同意・現在のアドレス、PRI／UTF-8／文字の除去、分割CRLF・長さ境界、件数・量・保持・期限、停止・選択・消去・世代・更新制限を確認する。実ループバックではUDP/TCP受信、実送信元IP、長すぎるUDP、TCPの未完行、使用中ポートの拒否、停止後の再bindを確認した。試験用の動的ポート／短い期間は内部フィクスチャのみで、製品の設定検証を緩めない。
