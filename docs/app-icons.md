# 実アプリアイコン（2026-10-25）

## 表示と識別の境界

通信マップ、接続先ヘッダー、通信詳細、アプリ一覧、履歴、ルール一覧で共通のAppIconを使用する。macOSが返すアイコンは表示専用であり、署名・本人性・安全性・保護状態の証明ではない。英語・日本語・简体中文のツールチップで区別する。アプリ名からブランドを推測する従来のロゴ表示は廃止し、未取得時はAppWindowアイコンへ戻す。画像は装飾として扱い、名前は既存のテキストに残す。

Rustのapplication_iconは任意のファイルパスを受け入れない。現在の実測接続・実測履歴にある正確なappKey、またはその観測が保持する有効な署名キーを共有状態で照合する。署名キーは画像を探す検索条件ではなく、観測済み実行ファイルへの参照である。保存／インポートされたルールだけでは取得しない。デモでは取得せず、取得後もモードと対象パスを再照合する。画像を署名検証・ルール照合へ渡さない。

ローカルファイルシステム上の存在する実行ファイルをcanonicalizeし、Contents内のAPPLバンドルを確認する。正常な外側のappがある場合は、そのアイコンをネストしたhelperにも使う。Info.plistは64KiBまで。バンドルが不明・不正・読めない場合、CLI、ネットワークボリューム等は汎用表示。表示名やBundle IDによる全ディスク検索、アプリ起動、外部URLの取得は行わない。

## 実装と上限

NSWorkspace.iconForFileの画像をコピーし、専用の単一ワーカーで96×96のRGBAビットマップに描画する。ビットマップは先にゼロクリアし、専用GraphicsContextとautoreleasepoolで処理する。AppKitオブジェクトはスレッドを跨がせない。最大48KiBのPNGだけをdata URLとして返し、JSでも形式・PNGヘッダー・寸法・長さを検査する。画像デコード失敗も汎用表示へ戻す。大容量描画フレームやGPUデータは転送しない。

Rustの待ちキューは16件、キャッシュは128件、成功60秒・失敗15秒。バンドル、Info.plist、宣言されたicns、Assets.carのメタデータ変化でも失効する。OSやFinderのキャッシュが最新画像を返す保証はない。要求は4秒で待機を打ち切り、期限切れキューを捨てる。実行中のOS APIは強制取消できないため、単一ワーカーを維持し、遅い呼び出しで無制限のスレッドを増やさない。

WebView側は表示範囲付近だけを読み込み、同一subjectを重複排除する。キャッシュと待機要求は各128件、同時IPCは4件、開始まで4秒を超えた要求は送信しない。画面外・デモ切替・対象変更では遅延応答を表示しない。取得元ごとの小さなPNGは表示用キャッシュであり、文書／ルール／保護状態はRustが引き続き所有する。
