# LAN TCP確認の実行条件（2026-10-26）

## 優先した理由

既存のLAN機器→TCP→サービス→診断という導線を維持したまま、遅い機器の確認と低負荷な調査を選べるようにする。リモート対象や対象範囲の拡大より先に、現在の一対象の確認を扱いやすくする。

## 実行条件と表示

| 条件 | 範囲 | 既定 |
| --- | --- | --- |
| 同時接続 | 1〜8 | 4 |
| TCP接続待機 | 100〜3000ms | 600ms |
| バッチ間隔 | 0〜1000ms | 0ms |
| 最大ポート数 | 1〜256 | 256 |

低負荷（1／600ms／250ms／64）、標準（既定）、長めに待つ（2／2000ms／100ms／64）の3プリセットと、数値調整を用意。プリセット変更・入力・表示切り替えでは確認を開始しない。対象は引き続き、既存の条件で収集・検証したLANアドレス1つだけ。送信元・インターフェース・IPv4／IPv6のスコープ制限を維持し、TCP接続後はサービスデータを送らず閉じる。

次回用の入力はウインドウ内の表示状態で、OS設定やルールは変更しない。実行時に確定した条件はRustのPlan／共有Snapshotに持ち、確認中は編集を無効化。完了後に入力を変えても結果の条件は変えない。再起動後の既定は従来と同じ4接続／600ms。

リングと4つの数値で、開放・接続拒否・不確定・未確認を表示する。タイムアウト・権限拒否・到達不可・取得エラーを「不確定」に含め、まだ結果がないポートは「未確認」とする。転送量・遮断実績・機器の安全性の表示ではない。実行条件はリング下に、送信元・要求ポートは情報アイコンに表示。3言語、キーボード操作、狭幅、reduced motionに対応。

## 予算・停止・差分

接続と間隔の見積りは`ceil(件数 / 同時数) × 接続待機 + (バッチ数 − 1) × 間隔`。RustとWebViewの両方で範囲と件数を検証し、120秒を超える組合せを開始前に拒否する。

別途、ワーカーにも単調時計による120秒の処理予算を設ける。見積りはOS／経路確認の時間を含まない。各接続の待機は残予算へ切り詰め、バッチ間の待ちは10ms以下に分ける。停止・ネットワーク確認前後・接続終了後・結果採用前・最終完了前に確認し、取消済み／予算切れ／送信元変更後の遅い結果を採用しない。予算切れは`failed`＋`port_budget_exceeded`として未完了のまま残す。実行中の接続やOS処理の終了待ちは必要になる場合がある。停止の共有世代フェンスと更新インストール排他は既存のRust状態管理を維持する。

比較の条件へ4つの実行条件を追加。同じ対象・送信元・マスク・インターフェース・LAN世代・ポート集合でも設定が違えば比較基準を破棄する。途中停止・予算切れ・不完全な結果は次の基準へ昇格しない。時間だけの変化は引き続き差分にしない。

CSVは従来の26列に`scan_concurrency`／`connect_timeout_ms`／`batch_interval_ms`／`max_ports`／`job_budget_ms`を追加した31列。入力中の設定ではなく、結果に対応する条件を出力する。全結果・途中停止・差分・BOM／CRLF・数式対策を維持。

サービス応答確認は別のジョブであり、今回の設定を暗黙に引き継がない。既存サービス確認の接続待機は600msのまま。

## 検証範囲

- TypeScript: 境界値、不正値、件数／処理予算、プリセット、不確定と未確認の集計、翻訳を検証。
- Rust: 設定のdeserialize／上限、実ワーカーへ渡す待機と並列数、停止・予算切れ・ネットワーク変更時の遅い結果拒否、間隔中の停止、比較基準の失効、31列CSVを検証。ワーカー試験は注入したネットワーク観測／接続結果を使い、LANへは接続しない。
- 実TCP: 明示的なignored試験で、1800ms設定のソケットをIPv4／IPv6のlo0ループバックだけに接続し、開放・接続拒否と送信元を確認。
- ブラウザー: Vite上のコンポーネント検証ハーネスとテスト用IPCで、JA／EN／简体中文 × 1500／768／375／320pxのプリセット・上限拒否・引数・開始／停止・編集ロック・条件保持・リング・CSV呼び出し・予算切れ表示を検証。実LAN／外部HTTPS要求なし。

実LANの遅延・損失、VPN／経路切替、実Tauriの複数ウインドウ・WebKit／Retina、署名済み配布版での通し確認はPending。リモート／複数対象への条件設定、UDPは後続。
