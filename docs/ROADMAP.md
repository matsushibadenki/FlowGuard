## 4. セキュリティ診断

管理対象の機器・サーバーを選び、ネットワーク調査とサービス確認の結果を利用して診断する。まず設定と公開状態を読み取り中心で確認し、認証済みの内部診断、脆弱性情報との照合へ段階的に広げる。

- 🔴 [Later] 第1段階：TLS証明書の期限・ホスト名一致・信頼検証、対応するTLS設定、HTTPのHTTPSへの誘導とセキュリティヘッダー、管理用サービスの到達性を確認。公開ポートだけで危険と断定せず、サービスの用途・想定する公開範囲と照らして診断する。
- 🔴 [Later] 第2段階：登録したサーバーへSSHで認証し、取得可能な更新状況、SSHの認証設定、不要な稼働サービス、待受アドレス、コンテナの公開設定を読み取り専用で確認。権限不足・非対応・未実施を正常判定から区別する。
- 🔴 [Later] 第3段階：確認した製品・バージョンをベンダーのアドバイザリやCVE情報と照合。取得日・情報源・更新状態を示し、バージョン非公開、バックポート、識別の曖昧さがある場合は脆弱性の候補として扱う。情報源の更新はRust側で管理し、外部へ診断対象の情報を送る場合は内容と送信先を明示する。
- 🔴 [Later] 診断概要に対象・実施範囲・完了数・未確認数・重要度別件数を表示。検出事項シートには対象、分類、重要度、確認済み／要確認／未実施、診断項目、観測根拠、影響、推奨対応、情報源、確認時刻を表示する。重要度と判定の確かさを分け、未実施を含む結果に一律の「安全」表示を付けない。
- 🔴 [Later] 診断履歴、前回との差分、対応済み・再確認待ち・対象外の理由を記録。検索・絞り込み・詳細パネル、CSV／HTMLレポート出力と再診断を備える。認証情報や秘密値は結果・ログ・レポートへ含めない。
- 🔴 [Later] 対象・項目・接続方法・タイムアウト・同時実行数を指定して手動開始・停止できるようにする。診断ジョブと根拠はRust共有状態で管理。通常診断に攻撃コードの実行、パスワード試行、設定の自動修正を含めない。
- ⭕️ [Pending] 実装後の検証：既知の問題を設定した管理下のテストサーバーで、検出漏れ・誤検出・権限不足・中断を確認。TLS終端・リバースプロキシ・OS差・更新情報の鮮度による判定限界を検証する。

「保存済み」「設定保存」「ポリシー適用確認」「個別通信の遮断」は別の状態です。署名なしでは適用確認を報告しません。署名済み環境での適用確認はProviderの応答を意味し、個別通信の遮断証明ではありません。

## 5. AI Security・既存ルーター連携

参照設計: ChatGPT「AI防御アプリ開発可否」（2026-10-14）。既存のMac観測・Network Extensionを維持し、Router/Mac → Rust Detector → Local LLM Analyst → 検証済み防御提案の順で拡張する。AI分析は通信経路外で非同期実行する。ウインドウは状態を所有せずRustの共有Snapshotを表示する。大規模描画は既存wgpuへ接続する。

### Phase 1 — 統合データモデル

- 🟢 [Done] Rustの`SecurityFlow`・`SecurityEvent`・3状態の`RouterCapabilities`とTypeScript型、共有Snapshotを追加。既存Connectionを変更せず現在のMacソケット観測を正規化。観測元付きIDによる同一サンプル内重複排除、最大1024件、デモ識別、観測失敗時の空結果を維持。
- 🟢 [Done] lsofでは確定できない開始方向はunknown、取得できない送受信量はnull。初回観測時刻とサンプル取得時刻を分離。ルーター能力は未確認、イベントは未検知として空のまま扱う。
- 🟢 [Done] [RouterAdapter共通基盤](router-adapters.md)を実装。読み取りと制御を別traitに分離し、構造化エラー・最大30秒の期限・停止・最大2ワーカーを共通化。制御は対象・操作・有効期限・認証済み相手に一致する不透明な権限を別途要求し、読み取り経路から発行／実行しない。実機アダプター・制御権限の発行・設定変更は未実装。
- 🟢 [Done] Rust共有状態に収集元登録・収集・停止・削除と世代フェンスを追加。最大8元・各128行・応答1MiBのschema 1入力を原子的に検証。構成済みIP endpoint／native transportの認証根拠とpayloadのsource IDを照合し、偽の認証・PID・アプリ情報をpayloadから受け付けない。古いsequence・不正な時刻・型・件数・重複の矛盾を拒否し、IPv6スコープ・nullと実測0・収集位置・失敗／鮮度を保持する。
- 🟢 [Done] 同一元内の重複排除と、認証済みLAN側観測のみを対象としたMacソケットとの候補照合。IP／ポート／protocolと近い時刻を照合し、最大512リンク。NAT後・匿名・位置不明・デモを除外し、レコード削除・通信量合算・PID／所有アプリの推定を行わない。共有Snapshotへ出力し、デモとは分離。登録はセッション内のみ、起動時に自動接続しない。Rust 97・TypeScript 84テストとビルド成功。
- ⭕️ [Pending] 管理下の実ルーターでの認証・送信元証明・カウンターの意味・収集位置・再起動／スリープ・実ネイティブUI連携。共通基盤の合成アダプター試験を、機器への接続・制御や認証の実証として扱わない。機種別アダプター・Router Management UIは下記Phase 2で実装する。

### Phase 2 — 読み取り専用ルーター監視

- 🟢 [Done] [Syslog手動受信](syslog-receiver.md)をRust共有状態・Tauriコマンド・3言語画面へ接続。待受IPv4／非特権ポート／管理対象の送信元IPv4／UDPまたは改行区切りTCP／受信時間と「IP制限は認証ではない」確認を指定する。既定は停止、5514番・5分。起動時の待受・自動再開・ルーターやOS設定変更・送信元への能動接続は行わない。
- 🟢 [Done] 1件4096バイト、毎秒20件／64KiB、保持256件、総読取8MiB／20000フレーム、TCP同時2接続・無通信2秒・合計1000接続、最長15分。超過・不正形式・対象外IP・未完行・保持破棄を区別し、ネットワーク上の欠落／偽装は判定不能と表示する。bind成功・受信待ち・受信保存・停止／期限／上限／失敗を区別し、ローカルアドレスの変化で終了する。
- 🟢 [Done] PRI付きUTF-8本文は全件未検証。送信側時刻・名前・PID／権限を信頼せず、制御文字除去を表示。HTML等として実行せず、AI送信・SecurityEvent化・自動遮断に使わない。停止後は公開済み記録を固定し、消去・再開始の世代を検証。受信中の更新インストールを拒否。検索・申告レベルの絞り込み・50行ずつの表示・共有選択／本文詳細・停止後のメモリ消去を追加。Rust 103・TypeScript 88テストとビルド、ループバックUDP／TCPの2試験と3言語・狭幅画面の確認が成功。
- ⭕️ [Pending] 実LANの管理機器・実macOS画面の開始／停止／消去、ローカルネットワーク権限・受信拒否、経路変更／スリープ／VPN・実ロス／大量送信。ループバックと合成画面を、実機配送・完全性・送信元認証の証明としない。
- 🔴 [Later] IPv6、TLSによる送信元認証、TCP octet-counting、暗号化保存と保持期間、CSV、機器固有ログの構造化。現在はPRI付きテキストを受信する限定実装で、RFC全体の検証・診断は行わない。
