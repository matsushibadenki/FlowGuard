# サービス再確認の差分

2026-10-25。ネットワーク経由で取得したサービス応答を、同じ条件の直前の完了結果と比較する。安全性・機器本人性・サーバー内部の正常性を判定する機能ではない。

## 比較条件と保存範囲

RustのSessionが基準を保持する。対象IP、送信元IP、ネットマスク、インターフェース、LAN収集世代、確認方式、正規化された任意HTTPS名、要求ポート集合がすべて一致した場合だけ比較する。ポートの順序は問わない。TCP操作番号が更新されても、この条件が一致していれば比較でき、CSVに新旧TCP操作番号を残す。

基準は最大64行の完了結果1件だけで、セッション終了時に失われる。比較結果に含める前回行にはさらに古い比較結果を含めず、履歴を再帰的に蓄積しない。画面を移動・検索・絞り込みしても通信を開始しない。既存の手動サービス確認と同じ送信先・上限を使う。

完了には、要求したすべてのポートが重複なく揃い、件数・操作・対象・送信元・収集条件がPlanと一致し、ジョブ全体のエラーがないことを要求する。途中経過、停止、失敗、不完全な結果は基準を置き換えない。確認条件が変わったときは旧基準を破棄し、LAN再収集・ネットワーク変更では比較を無効化する。停止済み操作・古い操作・無効化後の遅延応答を使って基準を復元しない。

## 判定と表示

| 表示 | 条件 |
| --- | --- |
| 観測情報が変化 | 前回と今回が応答確認済みで、状態・方式・サービス・申告製品／バージョン・応答・TLSバージョン・TLS検証情報のいずれかが異なる |
| 観測情報は同じ | 前回と今回が応答確認済みで上記情報が同じ。観測時刻だけの違いは無視 |
| 比較不確定 | どちらかがタイムアウト、TLS失敗、権限拒否、確認エラー、未対応、未識別など。HTTPSはTLS検証済みの情報も必要 |
| 比較なし | 基準なし、条件変更、確認中、中断／未完了。差分項目を確定しない |

ジョブ全体が完了していても、個別行は不確定になり得る。この完了結果は次回の基準になるが、不確定な行との比較を「同じ」と扱わない。TLSの比較対象は取得済みの検証結果と発行者・有効期間などの一部メタデータであり、証明書全体の同一性は保証しない。

日本語・英語・简体中文に対応。一覧に差分列と件数、変化・不確定のみの絞り込み、下部詳細に前回の応答・TLS情報・時刻を表示する。比較不可や旧収集の場合は差分絞り込みを無効にし、結果を隠さない。説明は情報アイコンから参照できる。
